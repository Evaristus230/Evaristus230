AWS CLOUD SUPPORT ENGINEERING PORTFOLIO
I am building this portfolio as a structured sequence of seven hands-on projects. Each project is designed to develop practical AWS administration and support skills through implementation, validation, troubleshooting, security review and technical documentation.

Lab standards: AWS Console-first implementation, corresponding AWS CLI verification, ca-central-1 as the default Region, cost-conscious resource selection, and cleanup of temporary resources.
Project roadmap
#	Project	Focus	Status
01	AWS Foundations & Account Operations	Account structure, global infrastructure, account verification, resource inventory, operational checks and cost awareness.	🟡 In progress
02	AWS IAM Identity Governance & Access Troubleshooting	Users, groups, roles, policies, access evaluation, identity inventory and access-denied investigation.	⚪ Planned
03	AWS VPC Network Architecture & Troubleshooting	VPCs, subnets, route tables, internet gateways, security groups, network ACLs and connectivity diagnosis.	⚪ Planned
04	AWS EC2 Infrastructure Support & Recovery	Instance lifecycle, AMIs, EBS, status checks, system logs, connectivity, recovery and monitoring.	⚪ Planned
05	AWS S3 Storage Security & KMS Encryption	Bucket configuration, access controls, Block Public Access, encryption, KMS keys, versioning and storage troubleshooting.	⚪ Planned
06	AWS Security Monitoring, Detection & Incident Investigation	CloudTrail, CloudWatch, audit events, log analysis, alerting, suspicious activity investigation and response documentation.	⚪ Planned
07	AWS Cloud Security Operations Capstone	Integrated cloud environment combining identity, networking, compute, storage, monitoring, security controls and operational runbooks.	⚪ Planned


What each project will demonstrate
01 — AWS Foundations & Account Operations
Establishing a reliable operational baseline for an AWS account.

Planned evidence includes:
- Account identity and access-context verification.
- AWS Regions, Availability Zones and service-scope investigation.
- AWS Console and AWS CLI account checks.
- Resource inventory and resource-location reporting.
- Tagging, ownership and cost-awareness fundamentals.
- Account operations documentation and troubleshooting runbooks.
02 — AWS IAM Identity Governance & Access Troubleshooting
Investigating how identities receive permissions and how access failures are diagnosed.

Planned evidence includes:
- IAM users, groups, roles and policies.
- Identity and access inventory.
- Policy inspection and permission reasoning.
- Access-denied troubleshooting scenarios.
- Identity security findings and remediation documentation.
03 — AWS VPC Network Architecture & Troubleshooting
Building and investigating the network foundations used by AWS workloads.

Planned evidence includes:
- VPC and subnet architecture.
- Route tables and gateway configuration.
- Security group and network ACL analysis.
- Connectivity tests and fault isolation.
- Network diagrams and troubleshooting records.
04 — AWS EC2 Infrastructure Support & Recovery
Supporting the lifecycle, availability and recovery of compute infrastructure.

Planned evidence includes:
- EC2 deployment and lifecycle operations.
- Instance status checks and system-log inspection.
- EBS volume and snapshot fundamentals.
- Security group and connectivity troubleshooting.
- Recovery procedures and operational notes.
05 — AWS S3 Storage Security & KMS Encryption
Configuring and investigating secure object storage.

Planned evidence includes:
- S3 bucket configuration and access controls.
- Block Public Access and bucket-policy review.
- Encryption at rest and AWS KMS fundamentals.
- Versioning and recovery considerations.
- Storage access and encryption troubleshooting.
06 — AWS Security Monitoring, Detection & Incident Investigation
Using AWS audit and monitoring services to understand account activity and investigate security events.

Planned evidence includes:
- CloudTrail event investigation.
- CloudWatch log and alarm configuration.
- Authentication and API activity analysis.
- Detection and alerting exercises.
- Incident investigation notes and response documentation.
07 — AWS Cloud Security Operations Capstone
Bringing the earlier projects together in an integrated operational exercise.

Planned evidence includes:
- End-to-end architecture documentation.
- Identity, network, compute and storage security controls.
- Centralised monitoring and investigation workflows.
- Troubleshooting scenarios and recovery procedures.
- Final architecture diagram, operational runbooks and project report.
Project status will only be changed when the relevant implementation, validation and documentation have actually been completed.

HOW I APPROACH ENGINEERING WORK
Stage	Engineering process
01	DISCOVER — Establish the environment, scope and reported problem.
02	ASSESS — Collect configuration, logs and other relevant evidence.
03	IMPLEMENT — Apply a controlled configuration or remediation.
04	VALIDATE — Test the expected behaviour and verify the result.
05	SECURE — Review permissions, exposure, resilience and cost implications.
06	DOCUMENT — Record the findings, commands, evidence and lessons learned.


I aim to make my work reproducible, clearly documented and useful as a technical reference. I distinguish between a successful lab demonstration and production experience.
